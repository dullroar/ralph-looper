# Operator: run the Jury through the Batch API under a USD cap

Operator step. The driver checks the gate and does not start an agent. Agents never hold the key.

## Cap

Set the number (USD, above 0 and at most 100 for the whole program) on the next line. The gate fails while the placeholder is there.

usd-cap: SET-BY-JIM

## Actions

1. In the main checkout, build the packets: `python3 -I tools/jury_packet.py --build --bundle --code`. Run `python3 plans/v4-es-1/gatelib.py packets verify` and check that the digest equals the record of `j01-packets`.
2. Choose a model that was not in the loop (not `claude-sonnet-5-5`). Build the input: `python3 -I tools/jury_requests.py build --packets review/packets --out <work>/jury-input.jsonl`. Build the requests: `python3 -I tools/batch.py build --input <work>/jury-input.jsonl --model <model> --prompt-file translation/prompts/batch-jury.md --out <work>/requests.jsonl`.
3. Run `submit --dry-run` and write the estimate in the record. Then `submit --requests ... --max-usd <the cap above> --cost-file <work>/costs.jsonl`. `<work>` is `$RALPH_WORK/aprende-a-programar-como-un-bicho-raro/v4-es-1/batch`, outside the repository.
4. When the batch ends: `status`, `collect` (batch prices), then `reconcile` with the pending file and the applied ledger. Write the replies with `jury_requests.py inbox --juror batch-<model> ...` into `review/inbox/`. Commit them on the step branch. They hold review text only, no key.
5. Write `plans/v4-es-1/records/j03-batch-jurors.md` with these lines: `batch-id:`, `juror-model:`, `dry-run-estimate-usd:`, `running-total-after-usd:` (from the cost file), `reconcile-ok: yes` and `packets-sha256:` (the manifest digest). No key, no secret.

## Do not change

- Files outside `touches`. The `gate`. Do not submit a second batch before the first is collected.

## Record

The driver sets `status: done` and writes `evidence` when the gate passes. Do not edit this file to mark it done.
