# Child spec: `bootstrap` in deterministic-controls

Wave `controls`. The target is a new repository made from `repo-template` in step 04. It has the template layout and its own copy of the template checks. This child builds release `v0.1.0`. Source phases: 1 to 4 and 7.

## Decisions to copy into the seed

- Package `deterministic_controls`, source layout `src/`. Python minimum from [decisions.tsv](../decisions.tsv). Standard library only at run time. Test with `unittest`.
- CLI: `python3 -m deterministic_controls {list,check,explain,version,adopt}`. `check --root DIR --profile quick|ci|full [--format text|json] [--report FILE]`.
- Exit codes: `0` pass, `1` defects found, `2` bad configuration or invocation, `3` internal failure. All nonzero codes fail CI. A crash never gives `0`.
- Result JSON: `schema_version`, `tool_version`, `repository_revision`, `control_revision`, `config_digest`, `profile`, `status`, and for each check `check_id`, `status` (`passed`, `failed`, `skipped` with reason, `error`), `duration_ms` and findings (`rule_id`, `severity`, `path`, `line`, `message`, `evidence`).
- Manifest `controls.toml`, `schema_version = 1`: profile, enabled check IDs, parameters. No commands. Unknown keys and unknown IDs are errors. A missing manifest is a configuration error (exit 2) with a clear message.
- Catalog: one file for each check, `src/deterministic_controls/catalog/<check-id>.toml` (ID, summary, version, status `experimental|advisory|required|deprecated`, default severity, parameters). With one file for each check, parallel steps never edit a shared catalog. `list` reads these files. It never imports project code to find checks.
- Severity is separate from policy. A policy maps severities to failure. A mandatory check that is missing or skipped fails.
- Checks are read-only. A fixer would need a separate `--fix` flag. It does not exist in `v0.1.0`.

## Step details

- **b01.** Touches `pyproject.toml`, `src/deterministic_controls/{__init__,__main__,cli}.py`, `src/deterministic_controls/core/**`, `src/deterministic_controls/catalog/` (empty loader only), `tests/test_contract.py`, `tests/test_cli.py`. Tests: unknown ID, bad manifest, missing manifest, internal exception (exit 3 with an `error` status), a skipped mandatory check fails, two runs give identical JSON except timing. Gate: `python3 -m unittest discover -s tests -v && python3 scripts/check_context.py && git diff --check`.
- **b02.** Touches `src/deterministic_controls/checks/plans.py`, `catalog/plans.schema.toml`, `catalog/plans.graph.toml`, `tests/test_plans.py`, `tests/fixtures/plans/**`. Fixtures: one valid plan, and one bad plan for each rule: missing `gate`, `done` without evidence, unknown dependency, cycle, overlapping `touches` of runnable steps, shared serial lane, `id` not equal to the file name. Each test checks the rule ID, path, severity and exit code. A compatibility test runs the template's `scripts/check_plan.py` on the same fixtures and on this repository and compares the pass or fail result.
- **b03.** Touches `.github/workflows/controls.yml`, `controls.toml`, `tests/test_consumer.py`, `tests/fixtures/consumer/**`. The workflow runs on `pull_request`, `push` to `main` and `workflow_dispatch`. No path filters. `permissions: contents: read`. Actions pinned to full SHAs. It runs the unit tests and `python3 -m deterministic_controls check --root . --profile ci --format json --report "$RUNNER_TEMP/controls.json"`, then uploads the report. Keep the template's `context` job until b09. The consumer test installs the package from the worktree into a temporary virtual environment and runs it on a good and a bad consumer fixture.
- **b04 to b07.** Each touches only its module, its catalog file, its test file, its fixture directory and its step file. Each has a good fixture, bad fixtures for each rule and a compatibility test against the template script where one exists. b05 fixtures: Unicode, percent-encoded paths, duplicate headings, reference links, fenced code, file names with spaces, absolute paths, links into `plans/archive`. b07 default patterns: `driver.out`, `ledger.jsonl`, `*.lock` under plan folders, `.claude/settings.json`, `.claude/settings.local.json`, `.env`, and a configurable list (the translation repository adds `review/canaries.key.json` and `review/packets/**`).
- **b08.** Touches `src/deterministic_controls/adopt/**`, `tests/test_adopt.py`, `tests/fixtures/adopt/**`, `adoption/repos.example.toml` (no real targets). It does not touch the catalog. `audit` is read only and classifies a repository (template-derived or not, languages, CI files, test commands, current checks, case-sensitive path issues) as `compliant`, `partial`, `needs-shims`, `not-suitable` or `blocked`. `plan` prints the diff it would make. `apply` works only on a clean tree, on the current branch, never pushes, never changes settings, is idempotent (a second run changes nothing) and keeps project-specific scripts and CI. It writes `scripts/check_context.py` as a shim that keeps the old output lines and exit codes, and `scripts/controls-requirements.txt` with the pinned install line. The shim runs the library from a cached virtual environment for the pinned commit (under `$XDG_CACHE_HOME/deterministic-controls/<commit>/`, default `~/.cache/...`). It creates that environment on first use (network needed once) and fails with exit 2 and a clear message if it cannot. It never falls back to the old scripts or to a pass. `apply` also writes `controls.toml`, and a `controls` job in `.github/workflows/context.yml` that keeps the existing job names. `receipt` writes the adoption receipt JSON with the fields of section 8.2 of the source plan.
- **b09.** Touches `tests/test_mutation.py`, `tests/test_metamorphic.py`, `tests/fixtures/mutation/**`, `docs/fault-matrix.md`, `controls.toml`, `scripts/check_context.py`, `.github/workflows/context.yml`. Mutations: remove a `gate`, rename a dependency, change a heading target, weaken a token pattern, drop an index line. Each mutation must turn a pass into the expected failure. Metamorphic: file order and repeated runs do not change findings. Fail closed: exceptions, timeouts and unreadable files give `error` and a nonzero exit. Measure 100, 1,000 and 10,000 synthetic Markdown files and record the times. Replace this repository's own `scripts/check_context.py` with the shim, so the repository dogfoods its own package.
- **b10.** Touches `README.md`, `docs/**` except `docs/fault-matrix.md`, `CHANGELOG.md`, `scripts/release_check.sh`, `pyproject.toml` (version only). `release_check.sh` runs the tests, the self check and a wheel build (`python3 -m pip wheel . --no-deps -w "$tmp"`) and prints the SHA-256 of the wheel. The docs include: install, run, read a failure, upgrade with a pull request, roll back to the previous pin, the security limits (best-effort secret scan, what CI can and cannot enforce), and the release policy (SemVer, immutable tags, release notes with added, changed, renamed and retired checks).
- **b11.** Touches its step file only. Clone the worktree into a temporary directory and run `bash scripts/release_check.sh`. Record test counts, the fault matrix summary, the timings and the wheel digest.
