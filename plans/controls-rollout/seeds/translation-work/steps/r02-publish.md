# Operator: publish the repository and tag `v4-es.1`

Operator step. The driver checks the gate and does not start an agent. This is the release. Only Jim does it, and only when Jim says "publish".

1. Check that `r01-release-gates` and `j10-gate-7` are `done`, and that `git status` of the release commit is clean.
2. With your own credentials: make the repository public, push the release commit, tag `v4-es.1`, push the tag and create the release with the PDFs and the EPUBs of the build. The names of the assets must be the names in `plans/v4-es-1/records/r01-release-gates.md`.
3. Write `plans/v4-es-1/records/r02-publish.md` with `repo-url:` (the public HTTPS GitHub URL, for example `https://github.com/<owner>/<repository>`) and `published-on: <date>`. The gate asks the public remote, without credentials, for the tag `v4-es.1`.
4. After publication, check the Spanish-edition links of the upstream package (see `u03-upstream-pr`). The adoption steps of `u05-adopt-upstream` need this.
